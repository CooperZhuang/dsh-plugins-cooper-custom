# 抽取召回率审计（50 个真实会话）

从 Mubea_Invoice-Insight 的 87 个真实会话里均匀抽 50 个，逐会话做三件事：

1. **标注该记的（gold）**：这段对话里未来会话会用得上的持久事实（决策与理由、约定/口径、环境/工具、踩坑、偏好、流程）。
2. **对比实际**：插件从这段对话实际写入的记忆标题，逐条判 gold 是否被覆盖。
3. **挑噪声**：插件记了但不该记的（一次性状态、代码可查、易变数字）。

标注由子代理读原始对话完成，可在 `~/.dsh/sessions/` 复核。

## 结果

| 指标 | 值 |
| --- | ---: |
| 会话数 | 50 |
| 该记的事实（gold） | 247 |
| 被覆盖 | 186 |
| **覆盖率** | **75.3%** |
| 平均分（0-5） | 3.82 |
| 漏记 | 61 |
| 噪声 | 41 |

分数分布：5 分 9 个、4 分 27 个、3 分 6 个、2 分及以下 8 个。

## 漏记的主要原因

- **子代理任务报告里的技术结论**：会话 42-48 这类「实现/审计报告」，插件把任务边界、验证命令当记忆，却漏掉报告里的机制设计与接口陷阱（如「接入无并发闸门：查原件→算 sha→INSERT 是 check-then-act」）。
- **跨会话的环境/路径事实**：如「PC 无 rsync，跨机同步用 ssh tar 流」「PC 推不上 origin 时用 git bundle 经 Mac 中转」。
- **大会话只抽 5 条**：会话 12（16 条 gold）只覆盖 5 条——抽取上限 `extractMaxMemories` 是 5。

## 噪声的主要原因

- **一次性任务状态/评审结论**（23 条）：如「Task 1 已提交 f738778」「设计文档 rev3 已通过评审」「task-2 验证命令」。
- **代码/git 可查**（11 条）：如「新增 6 个 i18n key」「既有入口文件清单」「已修复的 bug」。
- **易变快照**（1 条）。

## 复现

```sh
# 1. 抽样并准备（读真实会话 + 插件记忆）
python3 /tmp/prep_audit.py
# 2. 子代理逐会话标注（见 extract-audit.json 的 missed/noise）
```

原始对话与标注明细见 `extract-audit.json`（不含完整对话，只有事实条目）。
